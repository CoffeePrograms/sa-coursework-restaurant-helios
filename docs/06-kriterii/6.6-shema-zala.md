# 6.6. Схема зала

## US-18. Схема зала {#us-18}

**Как менеджер, я хочу создавать и редактировать схему зала, чтобы сотрудники выбирали места для обеда.**

Связь: [БП-02](../01-biznes-trebovaniya/1.5-biznes-processy.md#bp-02) «Управление схемой зала».

Сервисы: BFF, Hall.

Статус: спринт 3, частично: проверки пересечения столов ([AC-3](#us-18-ac-3)), признака публикации ([AC-4](#us-18-ac-4)) и проверки броней при удалении ([AC-5](#us-18-ac-5)) в коде нет, см. [раздел 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md).

Критерии приемки приведены в [таблице 6.13](#tablitsa-6-13).

Таблица 6.13 — Критерии приемки [US-18](#us-18)
{: #tablitsa-6-13 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-18-ac-1"></span>AC-1. Создание схемы | Допустим менеджер открыл редактор схемы зала<br>Когда он задает размеры зала, расставляет столы и места и сохраняет схему<br>Тогда схема сохраняется |
| <span id="us-18-ac-2"></span>AC-2. Подписи на схеме | Допустим менеджер редактирует схему<br>Когда он добавляет подпись, например «Стол №1» или «VIP-зона»<br>Тогда подпись отображается на схеме |
| <span id="us-18-ac-3"></span>AC-3. Пересечение столов (негатив) | Допустим менеджер поставил стол поверх другого стола<br>Когда он сохраняет схему<br>Тогда система не сохраняет схему и показывает пересекающиеся столы |
| <span id="us-18-ac-4"></span>AC-4. Публикация | Допустим схема сохранена<br>Когда менеджер публикует ее<br>Тогда сотрудники видят схему при бронировании ([US-04](6.2-bronirovanie-obeda.md#us-04) «Выбор места за столом») |
| <span id="us-18-ac-5"></span>AC-5. Удаление схемы с бронями (негатив) | Допустим на схеме есть места, занятые на сегодня<br>Когда менеджер удаляет схему<br>Тогда система не удаляет схему и сообщает, что по ней есть брони<br>Основание: [ОГР-09](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-09) «Удаление данных с бронями» |

Открытый вопрос: что происходит с бронями, если менеджер меняет схему зала, на которой уже заняты места.
