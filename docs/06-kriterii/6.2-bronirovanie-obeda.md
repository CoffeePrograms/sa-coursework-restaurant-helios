# 6.2. Бронирование обеда

## US-03. Выбор блюд {#us-03}

**Как сотрудник, я хочу видеть меню на сегодня и выбирать в нем блюда, чтобы заказать себе обед.**

Связь: [БП-03](../01-biznes-trebovaniya/1.5-biznes-processy.md#bp-03) «Бронирование обеда».

Сервисы: BFF, Menu, Lunch.

Статус: спринты 1 и 5, частично: на экране сотрудника раздел типа без блюд показывается ([AC-4](#us-03-ac-4)), см. [раздел 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md).

Критерии приемки приведены в [таблице 6.2](#tablitsa-6-2).

Таблица 6.2 — Критерии приемки [US-03](#us-03)
{: #tablitsa-6-2 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-03-ac-1"></span>AC-1. Меню на сегодня | Допустим менеджер назначил меню на сегодня<br>Когда сотрудник открывает бронирование с компьютера или телефона<br>Тогда он видит блюда меню, сгруппированные по типам, и описание каждого блюда<br>Основание: [ОГР-02](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-02) «Бронирование на текущий день»<br>Основание: [НФТ-14](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-14) «Браузеры и экраны» |
| <span id="us-03-ac-2"></span>AC-2. Выбор блюд | Допустим сотрудник открыл меню на сегодня<br>Когда он выбирает по одному блюду нужных типов<br>Тогда выбранные блюда попадают в его обед<br>Основание: [ОГР-07](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-07) «Одно блюдо каждого типа» |
| <span id="us-03-ac-3"></span>AC-3. Второе блюдо того же типа | Допустим сотрудник выбрал суп<br>Когда он выбирает другой суп<br>Тогда в обеде остается только последний выбранный суп<br>Основание: [ОГР-07](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-07) «Одно блюдо каждого типа» |
| <span id="us-03-ac-4"></span>AC-4. Тип без блюд | Допустим в меню на сегодня нет блюд одного типа, например напитков<br>Когда сотрудник открывает меню<br>Тогда раздел этого типа не показывается |
| <span id="us-03-ac-5"></span>AC-5. Меню на сегодня нет (негатив) | Допустим меню на сегодня не назначено<br>Когда сотрудник открывает бронирование<br>Тогда он видит сообщение, что меню на сегодня нет, и не может оформить обед |
| <span id="us-03-ac-6"></span>AC-6. Меню на другую дату | Допустим менеджер назначил меню на завтра<br>Когда сотрудник открывает бронирование<br>Тогда он видит и может выбрать только блюда из меню на сегодня<br>Основание: [ОГР-02](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-02) «Бронирование на текущий день» |

## US-04. Выбор места за столом {#us-04}

**Как сотрудник, я хочу выбрать место за столом на схеме зала, чтобы обедать в удобном месте.**

Связь: [БП-03](../01-biznes-trebovaniya/1.5-biznes-processy.md#bp-03) «Бронирование обеда».

Сервисы: BFF, Hall, Lunch.

Зависит от: [US-18](6.6-shema-zala.md#us-18) «Схема зала».

Статус: спринт 3, частично: занятость места проверяет только интерфейс, сервер сохраняет вторую бронь на то же место ([AC-3](#us-04-ac-3), [AC-4](#us-04-ac-4)), см. [раздел 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md).

Критерии приемки приведены в [таблице 6.3](#tablitsa-6-3).

Таблица 6.3 — Критерии приемки [US-04](#us-04)
{: #tablitsa-6-3 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-04-ac-1"></span>AC-1. Схема со свободными местами | Допустим менеджер сохранил схему зала<br>Когда сотрудник выбирает время обеда и открывает схему<br>Тогда он видит свободные и занятые места на это время<br>[Допущение: место считается занятым в рамках одного времени обеда: 12:00 или 13:00] |
| <span id="us-04-ac-2"></span>AC-2. Выбор свободного места | Допустим сотрудник открыл схему зала<br>Когда он выбирает свободное место<br>Тогда место закрепляется за его обедом |
| <span id="us-04-ac-3"></span>AC-3. Занятое место (негатив) | Допустим место на выбранное время уже занято<br>Когда сотрудник пытается его выбрать<br>Тогда система не дает выбрать это место<br>Основание: [ОГР-04](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-04) «Одно место на одно время» |
| <span id="us-04-ac-4"></span>AC-4. Одновременный выбор места (негатив) | Допустим два сотрудника выбрали одно свободное место на одно время<br>Когда оба подтверждают бронь<br>Тогда место получает сотрудник, чья бронь сохранена первой<br>И второй сотрудник видит сообщение, что место занято, и выбирает другое<br>Основание: [ОГР-04](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-04) «Одно место на одно время» |
| <span id="us-04-ac-5"></span>AC-5. Актуальность схемы | Допустим сотрудник открыл схему зала<br>Когда другой сотрудник бронирует место<br>Тогда это место отображается занятым без перезагрузки страницы (уведомление приходит через SignalR)<br>Основание: [НФТ-10](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-10) «Обновление схемы зала» |

## US-05. Подтверждение брони {#us-05}

**Как сотрудник, я хочу выбрать время обеда и подтвердить бронь, чтобы ресторан приготовил мой обед к этому времени.**

Связь: [БП-03](../01-biznes-trebovaniya/1.5-biznes-processy.md#bp-03) «Бронирование обеда».

Сервисы: BFF, Lunch, Hall.

Статус: спринт 2, частично: проверки брони выполняет только интерфейс ([AC-2](#us-05-ac-2)–[AC-5](#us-05-ac-5)), изменения и отмены брони в интерфейсе нет ([AC-6](#us-05-ac-6)), см. [раздел 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md).

Критерии приемки приведены в [таблице 6.4](#tablitsa-6-4).

Таблица 6.4 — Критерии приемки [US-05](#us-05)
{: #tablitsa-6-4 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-05-ac-1"></span>AC-1. Выбор времени | Допустим сотрудник оформляет обед<br>Когда он выбирает время<br>Тогда система предлагает два варианта: 12:00 и 13:00<br>Основание: [ОГР-02](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-02) «Бронирование на текущий день» |
| <span id="us-05-ac-2"></span>AC-2. Подтверждение брони | Допустим сотрудник выбрал блюда, время и свободное место<br>Когда он подтверждает бронь<br>Тогда система проверяет, что блюда входят в меню на сегодня и место свободно<br>И сохраняет обед с ФИО сотрудника из учетной записи<br>И обед попадает в список обедов на сегодня<br>Основание: [ОГР-07](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-07) «Одно блюдо каждого типа»<br>Основание: [ОГР-08](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-08) «Сотрудник в брони» |
| <span id="us-05-ac-3"></span>AC-3. Бронь без блюд (негатив) | Допустим сотрудник не выбрал ни одного блюда<br>Когда он подтверждает бронь<br>Тогда система не сохраняет обед и просит выбрать блюда<br>Основание: [ОГР-07](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-07) «Одно блюдо каждого типа» |
| <span id="us-05-ac-4"></span>AC-4. Время обеда прошло (негатив) | Допустим сейчас 12:20<br>Когда сотрудник выбирает время 12:00 и подтверждает бронь<br>Тогда система не сохраняет обед и сообщает, что это время уже прошло<br>Основание: [ОГР-02](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-02) «Бронирование на текущий день» |
| <span id="us-05-ac-5"></span>AC-5. Второй обед за день (негатив) | Допустим у сотрудника уже есть обед на сегодня<br>Когда он открывает бронирование<br>Тогда система сообщает, что обед на сегодня уже заказан, и не дает оформить второй<br>Основание: [ОГР-06](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-06) «Один обед в день» |
| <span id="us-05-ac-6"></span>AC-6. Изменение и отмена брони | Допустим у сотрудника есть обед на сегодня<br>Когда он меняет блюда, время или место либо отменяет обед<br>Тогда список обедов на сегодня показывает изменения<br>[Допущение: срок, до которого можно менять бронь, в исходных материалах не задан; логично ограничить его моментом отправки отчета ресторану] |
