# 6.4. Пользователи и роли

## US-12. Регистрация и вход по логину и паролю {#us-12}

**Как сотрудник, я хочу регистрироваться и входить по логину и паролю, чтобы пользоваться системой.**

Связь: [БП-05](../01-biznes-trebovaniya/1.5-biznes-processy.md#bp-05) «Управление пользователями и ролями».

Сервисы: BFF, Authorization.

Статус: спринт 2, реализовано.

Критерии приемки приведены в [таблице 6.8](#tablitsa-6-8).

Таблица 6.8 — Критерии приемки [US-12](#us-12)
{: #tablitsa-6-8 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-12-ac-1"></span>AC-1. Регистрация | Допустим пользователь открыл форму регистрации<br>Когда он вводит ФИО, логин и пароль и подтверждает регистрацию<br>Тогда система создает учетную запись<br>Основание: [ОГР-05](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-05) «Только сотрудники компании»<br>Основание: [НФТ-03](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-03) «Хранение паролей» |
| <span id="us-12-ac-2"></span>AC-2. Некорректные данные (негатив) | Допустим пользователь заполняет форму регистрации<br>Когда обязательное поле пустое или длиннее допустимого<br>Тогда система не создает учетную запись и показывает, какое поле исправить |
| <span id="us-12-ac-3"></span>AC-3. Логин уже занят (негатив) | Допустим учетная запись с таким логином уже есть<br>Когда пользователь регистрируется с этим логином<br>Тогда система не создает учетную запись и сообщает, что логин занят |
| <span id="us-12-ac-4"></span>AC-4. Вход | Допустим у пользователя есть учетная запись<br>Когда он вводит верные логин и пароль<br>Тогда система выполняет вход и выдает cookie сессии<br>Основание: [НФТ-01](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-01) «Защищенное соединение»<br>Основание: [НФТ-02](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-02) «Сессия пользователя» |
| <span id="us-12-ac-5"></span>AC-5. Неверный пароль (негатив) | Допустим у пользователя есть учетная запись<br>Когда он вводит неверный пароль<br>Тогда вход не выполняется, и система сообщает о неверных данных |

[Допущение: требования к сложности пароля в исходных материалах не заданы]

## US-13. Управление учетными записями и ролями {#us-13}

**Как администратор, я хочу управлять учетными записями и ролями пользователей, чтобы каждый получал доступ только к своим функциям.**

Связь: [БП-05](../01-biznes-trebovaniya/1.5-biznes-processy.md#bp-05) «Управление пользователями и ролями».

Сервисы: BFF, Authorization.

Статус: спринт 3, частично: удаление учетной записи не проверяет брони ([AC-4](#us-13-ac-4)), см. [раздел 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md).

Критерии приемки приведены в [таблице 6.9](#tablitsa-6-9).

Таблица 6.9 — Критерии приемки [US-13](#us-13)
{: #tablitsa-6-9 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-13-ac-1"></span>AC-1. Изменение данных пользователя | Допустим администратор открыл учетную запись пользователя<br>Когда он меняет ФИО или логин<br>Тогда система сохраняет изменения |
| <span id="us-13-ac-2"></span>AC-2. Назначение роли | Допустим администратор открыл учетную запись пользователя<br>Когда он назначает или снимает роль «Менеджер» или «Администратор»<br>Тогда права пользователя меняются по [таблице 2.2](../02-trebovaniya/2.1-roli-i-uchastniki-vzaimodeystviya.md#tablitsa-2-2)<br>И пользователь без этих ролей работает как сотрудник<br>Основание: [ОГР-01](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-01) «Назначение ролей» |
| <span id="us-13-ac-3"></span>AC-3. Удаление учетной записи (негатив) | Допустим администратор удалил учетную запись<br>Когда пользователь пытается войти<br>Тогда вход не выполняется, и система сообщает о неверных данных |
| <span id="us-13-ac-4"></span>AC-4. Удаление пользователя с обедом на сегодня (негатив) | Допустим у пользователя есть обед на сегодня<br>Когда администратор удаляет его учетную запись<br>Тогда система не удаляет учетную запись и сообщает, что у пользователя есть бронь<br>Основание: [ОГР-09](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-09) «Удаление данных с бронями» |
| <span id="us-13-ac-5"></span>AC-5. Нет прав администратора | Допустим пользователь вошел с ролью «Менеджер»<br>Когда он открывает систему<br>Тогда функции управления ролями ему недоступны<br>Основание: [ОГР-01](../02-trebovaniya/2.2-ogranicheniya-i-pravila.md#ogr-01) «Назначение ролей»<br>Основание: [НФТ-04](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-04) «Разграничение доступа на сервере» |

## US-14. Разграничение доступа по ролям {#us-14}

**Как администратор, я хочу, чтобы система показывала и выполняла только разрешенные роли функции, чтобы сотрудники не меняли меню и отчеты.**

Связь: [БП-05](../01-biznes-trebovaniya/1.5-biznes-processy.md#bp-05) «Управление пользователями и ролями».

Сервисы: BFF, Authorization.

Права ролей приведены в [таблице 2.2](../02-trebovaniya/2.1-roli-i-uchastniki-vzaimodeystviya.md#tablitsa-2-2).

Статус: спринт 2, частично: интерфейс скрывает недоступные функции, на сервере роль проверяется только для управления пользователями, см. [раздел 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md).

Критерии приемки приведены в [таблице 6.10](#tablitsa-6-10).

Таблица 6.10 — Критерии приемки [US-14](#us-14)
{: #tablitsa-6-10 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-14-ac-1"></span>AC-1. Скрытие недоступных функций | Допустим пользователь вошел в систему<br>Когда он открывает интерфейс<br>Тогда он видит только функции, разрешенные его роли по [таблице 2.2](../02-trebovaniya/2.1-roli-i-uchastniki-vzaimodeystviya.md#tablitsa-2-2) |
| <span id="us-14-ac-2"></span>AC-2. Проверка прав на сервере (негатив) | Допустим сотрудник отправляет запрос к функции менеджера в обход интерфейса<br>Когда BFF получает запрос<br>Тогда BFF отклоняет запрос с ошибкой доступа<br>Основание: [НФТ-04](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-04) «Разграничение доступа на сервере» |
| <span id="us-14-ac-3"></span>AC-3. Пользователь не вошел (негатив) | Допустим пользователь не вошел в систему<br>Когда он открывает любую страницу<br>Тогда система показывает страницу входа<br>Основание: [НФТ-02](../02-trebovaniya/2.3-nefunkcionalnye-trebovaniya.md#nft-02) «Сессия пользователя» |
