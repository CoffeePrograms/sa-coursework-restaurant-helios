# 2.2. Ограничения и правила

## ОГР-01. Назначение ролей {#ogr-01}

Роли назначает только администратор.

## ОГР-02. Бронирование на текущий день {#ogr-02}

Сотрудник бронирует обед только на текущий день, только на 12:00 или 13:00 и только на время, которое еще не прошло.

## ОГР-03. Меню с бронями не меняется {#ogr-03}

Меню нельзя изменить после того, как по нему оформлен хотя бы один обед.

## ОГР-04. Одно место на одно время {#ogr-04}

Одно место на одно время обеда может занять только один сотрудник.

## ОГР-05. Только сотрудники компании {#ogr-05}

В системе регистрируются только сотрудники компании. В MVP это не проверяется: любой зарегистрировавшийся пользователь считается сотрудником.

## ОГР-06. Один обед в день {#ogr-06}

У сотрудника не больше одного обеда на день. Пока обед на сегодня есть, второй не оформляется.

## ОГР-07. Одно блюдо каждого типа {#ogr-07}

В обеде хотя бы одно блюдо и не больше одного блюда каждого типа: суп, горячее, салат, напиток.

## ОГР-08. Сотрудник в брони {#ogr-08}

Бронь связана с сотрудником через ФИО из учетной записи: интерфейс передает его в поле personId. ФИО не уникально, поэтому целевое правило — связывать бронь с ID пользователя ([раздел 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md)).

## ОГР-09. Удаление данных с бронями {#ogr-09}

Блюдо, схему зала и учетную запись, по которым есть обед на сегодня, удалить нельзя. Удаленные блюдо и схема зала остаются в базе с признаком удаления, поэтому прошлые обеды и отчеты за прошлые дни не меняются.
