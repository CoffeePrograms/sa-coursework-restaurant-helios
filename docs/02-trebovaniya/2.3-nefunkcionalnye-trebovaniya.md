# 2.3. Нефункциональные требования

[НФТ-01](#nft-01)–[НФТ-10](#nft-10) сформулированы по коду и конфигурации проекта. [НФТ-11](#nft-11)–[НФТ-15](#nft-15) — целевые требования: значения с пометкой «допущение» нужно согласовать с заказчиком. Расхождения реализации с требованиями приведены в [разделе 7.2](../07-rezultat/7.2-naydeno-pri-revizii.md).

## НФТ-01. Защищенное соединение {#nft-01}

Веб-приложение и API принимают внешние запросы только по HTTPS. Запрос по HTTP перенаправляется на HTTPS. В Kubernetes TLS завершает Ingress, при запуске в Docker Compose — Nginx на порту 443. BFF передает заголовок HSTS.

## НФТ-02. Сессия пользователя {#nft-02}

После входа BFF выдает cookie сессии с признаками Secure и HttpOnly: cookie передается только по HTTPS и недоступна скриптам страницы. Сессия действует 7 дней. Запрос к защищенному эндпоинту без действующей cookie получает ответ 401.

## НФТ-03. Хранение паролей {#nft-03}

Authorization хранит пароли только в виде хеша (PasswordHasher из ASP.NET Core Identity). Пароль в открытом виде не хранится, не возвращается в ответах API и не записывается в журнал.

## НФТ-04. Разграничение доступа на сервере {#nft-04}

BFF проверяет права ролей по [таблице 2.2](2.1-roli-i-uchastniki-vzaimodeystviya.md#tablitsa-2-2) для каждого запроса. Запрос без входа получает ответ 401, запрос без нужной роли — ответ 403.

## НФТ-05. Журнал запросов {#nft-05}

BFF записывает каждый HTTP-запрос в журнал: время, уровень, метод, путь, код ответа, контроллер, пользователь, исключение. Записи передаются в Administration через RabbitMQ с постоянной доставкой (Durable) и хранятся в ClickHouse.

## НФТ-06. Срок хранения журнала {#nft-06}

Записи журнала хранятся не дольше 30 дней (допущение: срок нужно согласовать с заказчиком). Записи старше срока удаляются автоматически не реже раза в сутки, начиная с самых старых.

## НФТ-07. Мониторинг {#nft-07}

Prometheus опрашивает эндпоинты метрик сервисов и ClickHouse каждые 15 с. Для каждого сервиса собираются время ответа и доля ответов с ошибкой. Grafana показывает эти метрики за выбранный период на дашбордах «Сервисы» и «ClickHouse», записи журнала — на дашборде «Логи».

## НФТ-08. Сборка и развертывание {#nft-08}

Сборка запускается в GitHub Actions по тегу версии (v*): сборка решения, модульные тесты, сборка Docker-образов сервисов и публикация в GitHub Container Registry, развертывание в Kubernetes. Если тесты не прошли, образы не публикуются и развертывание не выполняется.

## НФТ-09. Хранилища данных {#nft-09}

Каждый сервис хранит данные в своей базе: Authorization и Lunch — в PostgreSQL, Menu и Hall — в MongoDB, журнал — в ClickHouse. Сервис не обращается к базе другого сервиса. Базы хранят данные на постоянных томах (PersistentVolumeClaim в Kubernetes, тома Docker при локальном запуске), данные сохраняются после перезапуска контейнеров.

## НФТ-10. Обновление схемы зала {#nft-10}

После сохранения брони BFF отправляет событие ReservationCreated через SignalR всем открытым экранам бронирования. Занятое место отображается без перезагрузки страницы. Открытый вопрос: допустимое время доставки события не задано.

## НФТ-11. Производительность {#nft-11}

Открытый вопрос: число одновременных пользователей и допустимое время отклика не заданы, нагрузочное тестирование не проводилось. Целевые значения нужно согласовать с заказчиком и проверить нагрузочным тестом.

## НФТ-12. Доступность {#nft-12}

Система доступна в рабочие дни с 9:00 до 15:00 по местному времени не менее 99% времени за месяц (допущение). Плановые работы проводятся вне этого окна.

## НФТ-13. Резервное копирование {#nft-13}

Базы PostgreSQL и MongoDB копируются раз в сутки, копии хранятся 7 дней (допущение). При сбое теряются данные не больше чем за сутки, восстановление из копии занимает не больше 4 часов (допущение). Журнал в ClickHouse в резервную копию не входит.

## НФТ-14. Браузеры и экраны {#nft-14}

Веб-приложение работает в двух последних версиях Chrome, Edge, Firefox и Safari на компьютере и на телефоне с шириной экрана от 360 пикселей (допущение). Бронирование обеда на телефоне выполняется без горизонтальной прокрутки.

## НФТ-15. Персональные данные {#nft-15}

ФИО и логин сотрудника — персональные данные. Их видят сам пользователь, менеджер в отчете и администратор. Пароли и тела запросов входа и регистрации в журнал не записываются. Обеды старше 30 дней удаляются.
