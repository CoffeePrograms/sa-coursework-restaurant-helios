# Глоссарий

| Термин | Определение |
| --- | --- |
| AC | Acceptance Criteria — критерий приемки пользовательской истории |
| AMQP | Протокол обмена сообщениями с брокером RabbitMQ |
| API | Application Programming Interface — программный интерфейс системы |
| BFF | Backend for Frontend — серверный слой для одного клиента: принимает запросы веб-приложения и собирает данные под экраны |
| C4 | Нотация описания архитектуры по уровням: контекст, контейнеры |
| gRPC | Протокол вызова удаленных процедур, по которому BFF обращается к сервисам |
| MVP | Minimum Viable Product — минимально жизнеспособный продукт |
| US | User Story — пользовательская история |
| Администратор | Пользователь со всеми правами, в том числе на назначение ролей |
| БП | Бизнес-процесс |
| Блюдо | Позиция меню с названием, описанием и типом |
| Время обеда | Время, на которое бронируют обед: 12:00 или 13:00 |
| Менеджер | Работник компании, который ведет меню и схему зала и передает заказы ресторану |
| Меню на день (меню на дату) | Блюда, доступные для выбора в конкретную дату. В модели данных — меню и запись расписания меню |
| НФТ | Нефункциональное требование |
| Обед (бронь) | Выбранные сотрудником блюда, время и место на текущий день. «Обед» и «бронь» — синонимы, в коде — Reservation |
| ОГР | Ограничение — правило, которое система соблюдает во всех историях |
| Отчет | Документ со списком обедов за день, который менеджер передает ресторану |
| ПДн | Персональные данные сотрудника: ФИО и логин |
| Расписание меню | Запись, которая назначает меню на дату |
| Ресторан | Организация, которая готовит обеды и принимает сотрудников в зале |
| Система (Helios) | Веб-приложение для бронирования обедов в ресторане |
| Список всех блюд | Блюда, из которых менеджер составляет меню |
| Список обедов | Все обеды сотрудников за день |
| Сотрудник | Работник компании, который бронирует обед |
| Спринт | Этап разработки длительностью 1 месяц |
| Схема зала | Расположение столов и мест в зале ресторана |
| Тип блюда | Суп, горячее, салат или напиток |
